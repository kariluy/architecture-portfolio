图 1 · 系统总体架构
分层 + 数据流转主线
监督者主从模式：主 Agent 统一调度、不直接执行；能力收敛在工具层；专项子 Agent 各司安全 / 记忆 / 具身
结构要点：三类触发统一汇入主 Agent，按意图类型经条件边路由到三个专项子 Agent 或直接走工具快路，再经协议适配与 MQTT 下发设备。主 Agent 从不直接碰设备——语义判断与物理执行之间隔着「工具层 + 协议适配」两层确定性代码，这是幻觉防线的第一道墙；原始音视频在边缘节点本地处理，仅上送结构化事件语义。
图 2 · 三档推理路由 + 复合多意图四步链路
意图识别全链路
规则优先、LLM 介入：高频确定性指令走快路，认知活才进主 Agent 规划
设计要点：把意图理解拆成「切分→分类→路由→依赖建模→冲突消解→聚合」的显式链路，而非端到端一次生成，使每一步可单测、可回溯、可挂规则快路；无依赖子意图并行执行、条件分支「编译注册、规则触发」，从机制上避免多意图串台与丢意图。高频确定性指令由小模型 + 规则直连，只在复合 / 歧义 / 复杂规划时才进 LLM。
图 3 · 复合多意图端到端拆解示例
一条指令走完全链路
「查明天天气 → 按天气联动 → 放歌」：并行执行 · 条件编译 · 离线降级
这条示例同时讲清五件事：任务图规划（DAG 节点/边）、并行编排（无依赖子任务立即执行）、条件编译（LLM 编译、规则触发、不轮询）、离线降级（本地能力优先）与应答路由（TTS 先行 + 失败纠正闭环）。
图 4 · 复杂时序任务规划引擎
规划-执行-监测-重规划闭环
条件任务「LLM 编译 + 规则执行」分离，避免 LLM 常驻轮询；重规划是增量补丁 + 次数护栏
规划不是一锤子买卖：接的是「规划→执行→监测→重规划」闭环。条件任务「LLM 编译、条件引擎执行、LLM 不轮询」——LLM 只在规划阶段把自然语言条件编译成事件表达式并注册到纯规则引擎，触发时刻由规则直接执行，避免常驻轮询的高延迟与不可靠；replanner 只重排未执行节点、单任务限 2 次、超限降级询问用户，状态经 checkpointer 持久化支持断点续跑。
图 5 · 对话与安全护栏链
高危写操作防幻觉
四层护栏 + 最小权限：高危设备不进 LLM 工具目录，写操作无旁路、全程审计
不进入 LLM 的 Function Calling 工具目录，只能走 App 或物理方式触发。 「不给权限优于叠加验证」——从源头杜绝幻觉误开门锁，而非事后拦截。 示例：门锁只订阅状态（开/关/未锁提醒）、不做控制；锁控走屋主物理动作或官方 App 三端统一对话 + 跨终端会话接力 手机 APP · 全屋音箱 · 机器人机载三端统一对话，复用同一套意图理解与工具层； 会话可在音箱与 App 之间无缝接力，写类高危操作统一走上方护栏链。
设计动机：大模型是概率模型，不能直接进入物理安全控制回路。写类高危操作走参数校验 → 状态预演 → 人工确认 → 执行审计四层护栏；高危设备直接移出 LLM 工具目录（最小权限），双重保证。越权 / 诱导指令在 120 条攻击集上的拦截率为 100%。
图 6 · 三层记忆中枢与场景自适应
长期偏好反哺规划
会话 / 短期 / 长期分层读写；写入门槛 + 冲突仲裁 + 遗忘机制控制质量与膨胀
记忆不是「记多少算多少」：三层分层读写，短期做噪声缓冲、长期向量化入库并与主 Agent 规划链路集成。写入门槛（重复 3 次 + 未纠正）、冲突仲裁（登录者优先 / 加权均值）、遗忘机制（30/90 天）三者共同控制记忆质量与规模，使「自适应」可预测、可解释，而非无约束累积。
图 7 · 多模态安全看护链路
两级视觉 + 多源融合 + 分级告警
边缘初筛命中才触发 VLM 复核，降低误报；止损自动、求助必由人
设计要点：两级视觉让重模型只在可疑帧上介入，兼顾实时性与精度；多源融合把误报率从 23% 降到 4.1%。处置边界明确——可逆止损动作由规则引擎秒级执行，不可逆的外部求助永远留给屋主：系统定位是「感知 + 止损 + 提醒」，不替用户做高后果决定。
图 8 · 机器人协作（V2）· 盲区主动复核 + 主动巡检
具身 · 双闭环
两条线（被动盲区复核 / 主动定时巡查）都汇入机器人决策子 Agent；决策与接口在中心机，导航采集由嵌入式侧实现
具身分工与双闭环：两条线（被动盲区复核、主动定时巡查）都汇入机器人决策子 Agent——由地图 + 盲区覆盖率 + 事件可疑度联合打分决定是否派机器人。算法侧参与「决策 → 结构化巡检目标 → 适配接口 → 回传 VLM 复核」这条线，导航/避障/拍照采集由嵌入式侧实现，二者以适配层解耦。
图 9 · 语音多模交互链路与延迟预算
唤醒 → TTS 全链路
流式压低首字延迟；规划期先播确认语解耦体感延迟；失败二次纠正
链路要点：唤醒 → VAD → 流式 ASR → 意图 → 规划 → 执行 → TTS。流式识别 + 端点检测压低首字延迟；复杂规划期间先播确认语使体感延迟与实际解耦，执行失败则二次播报纠正，保证「说了必有修正闭环」——这也正是任务 checkpoint 必须持久化的原因。
图 10 · 两级算力部署与隐私边界
中心机重模型 · 边缘轻模型
原始音视频在边缘节点本地处理，仅上送结构化事件语义，实现全离线
为什么两段而不是单点大模型：三点叠加——① 产品红线要求全离线、原始数据不出户；② 硬件拓扑决定了摄像头 / 传感器 / 音箱分散各房间，须边缘就近采集与设备直连；③ 家庭 7×24 常开的功耗、噪音与发热。因此是「中心机集中跑重模型 + 边缘盒跑轻模型」的分布式，而非单卡一把梭。
图 11 · 具身机器人 · 管家功能全景
具身 · 四功能 + 内网协同
机器人是「会走路的管家终端」：对话题主入口 + 视觉巡检 / 引路导航 / 主动联动三个管家动作；大脑统一在中心机，内网双向同步
机器人的核心作用：它是会走路的管家终端——对话题基本由机器人承载（走到身边就近交互），少数场景直接对房间固定拾音器说话；视觉巡检、引路导航、主动联动是它的三个管家动作。理解与决策仍集中在中心机，机器人只负责提出感知、执行动作，二者经家庭内网（全离线）双向同步结构化语义与指令；导航与采集采用成熟方案，语义理解、视觉复核、场景联动决策与适配接口做清晰分层。
